noteser is a browser-based notes app I have been building on weekends and evenings. Markdown files, wikilinks, tasks, live preview, two-way sync with a GitHub repo you own. There is no server, no database, no account. Your notes are plain `.md` files in your own repo. If noteser disappears tomorrow, your vault is still there, in git, version-controlled, readable in any editor.

Last week was launch week. I went from "ready enough for me" to "ready enough to show people," and I learned more in five days than I had in the prior month of building. This is the honest version of what shipped, what broke, and what I would do again.

## Day 1: harden the sync layer

I knew the first real user would test sync harder than I had, so day one was sync safety. Three things landed:

1. Auto-sync. Local edits get pushed in the background and remote edits get pulled, both throttled, both surfaced in the UI so you always know what state you are in.
2. Pull-only flows. When a user wants to "catch up" without pushing local changes, that is now a one-click action instead of an implicit side effect.
3. A delete safety net. A renamed file used to look like a delete-plus-add to the merge layer, which made true conflicts dangerous. The safety net catches those cases and routes them through the merge tab instead of writing through silently.

The pattern I keep coming back to with sync code: write the test first, then the fix. Sync bugs are subtle. The only way to know a fix actually fixed it is a test that fails before the fix and passes after.

## Day 2: post, monitor, get banned

I drafted a short post for r/ObsidianMD. It described what noteser is, what it is not, and why I built it. I posted it, then sat with the tab open for sixty minutes watching upvotes and the modlog.

The post was removed under the no-self-promotion rule. The mod was right. I had read the rule, convinced myself the post was educational rather than promotional, and posted anyway. It was promotional. The subreddit exists to talk about Obsidian, not adjacent projects. Lesson learned, and it cost me one post and zero karma I cared about.

Two things I would do differently. First, ask the mods before posting in a subreddit with a strict self-promo rule. Most of them say yes if you ask, and silently remove you if you do not. Second, lead with the problem, not the product. The version of the post that would have survived starts with "here is the workflow I wanted that Obsidian did not give me" and only mentions noteser at the end.

## Day 3: pivot the distribution, build the plugin platform

Reddit was clearly not the only channel. I sketched a list of places where the audience overlaps without the promotional friction: r/PKMS, r/selfhosted, Show HN, a small handful of newsletters. I did not post anywhere yet. The pivot was just admitting that distribution is its own project.

The rest of day three went into the plugin platform v1. Plugins run in a web worker, sandboxed, with capability-based permissions. You declare what the plugin needs (read notes, write notes, render a sidebar panel) in a manifest, and the user approves each capability before the plugin can touch the vault. Deny by default. The Obsidian model is trust-the-author, which works because the community is small and the authors are known. I wanted something that would still be safe if a stranger emailed me a plugin.

## Day 4: plugin v1.1, three reference plugins

Day four extended the plugin API with file I/O and shipped three reference plugins: a word count panel, a callout block renderer, and a PDF exporter. Reference plugins are how you find out what your API is missing. The word count one was trivial. The callout renderer needed a real markdown extension point, which I had not built yet. The PDF exporter needed a way for a plugin to render to a hidden DOM tree and then read that tree back, which I also had not built. Each one cost me an afternoon and improved the platform more than another week of designing in the abstract would have.

## Day 5: sidebar leaf model, calendar, tooltips

Day five was the refactor I had been avoiding. The sidebar was a hand-rolled mess of panels with ad-hoc state. I rebuilt it on the Obsidian leaf model: every panel is a tab in a group, every group is a split, splits compose. Once the model was right, weekly notes in the calendar became a thirty-line change, and the tooltip layer for sidebar icons became free because all icons share one component.

This is the kind of work that feels slow because nothing visible changes. The screenshot before and after is almost identical. But the next ten features all got cheaper, which is the only thing that matters at this stage.

## Three technical decisions worth talking about

1. **Plugins in a web worker with capability-based permissions.** Sandboxed code, declared capabilities, user approval per capability. Deny by default. It is more work than trust-the-author, but it is the only model I can defend to a user who is not me.

2. **The Obsidian leaf model for the sidebar.** Tabs in groups, groups in splits, splits compose. Once I committed to it, the sidebar stopped being a special case and became a normal part of the layout system. Most of my recent UI bugs are now layout bugs, not panel bugs, which is the correct kind of bug to have.

3. **GitHub as the cloud.** No server, no database, no account. Every note is a `.md` file in a repo the user owns. Real three-way merge per file, keyed on the last-pushed SHA. This decision did most of the hard work for me. Conflict resolution is git. Undo is git. Backup is git. Sharing is git. I borrowed thirty years of version control and pointed it at notes.

## What did not go well

The r/ObsidianMD ban. I underestimated how strictly community subreddits enforce self-promotion rules, and I posted without checking with the mods. The post was promotional, the rule was clear, and the removal was fair. The right move would have been to message the mods first, or to write a problem-first post that mentions the product once at the end. I will do that next time.

## What is next

A community plugin ecosystem, so plugins are not just my reference ones. Mobile polish, because the experience on a phone is still rough enough that I do not recommend it. Maybe a Show HN, once I have one more month of stability behind me. And more posts like this one, because writing down what I learned during the week is the part I almost always skip and almost always regret skipping.
